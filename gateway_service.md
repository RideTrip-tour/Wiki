### Работа сервиса `gateway_service`

`gateway_service` — это ключевой компонент в архитектуре микросервисного конструктора для активного отдыха, который выполняет роль API шлюза (API Gateway). Он принимает HTTP-запросы от клиентов (например, мобильных приложений или веб-сайтов) и перенаправляет их к соответствующим микросервисам. Этот сервис также выполняет функции маршрутизации, управления SSL-сертификатами, кэширования, логирования и мониторинга.

#### Основные задачи и функции:

1. **Маршрутизация запросов:**
   - `gateway_service` обрабатывает все входящие HTTP-запросы и перенаправляет их к нужному микросервису.
   - Он настроен для работы с несколькими микросервисами, такими как `auth-service`, `users-service`, `activities-service`, `pricing-service` и другими.
   - Каждый запрос проходит через конфигурацию Nginx, который проверяет запросы и проксирует их к соответствующим сервисам. Маршрутизация основана на пути запроса, например:
     - `/auth` — запросы передаются в `auth-service`.
     - `/users` — запросы передаются в `users-service`.
     - `/pricing` — запросы передаются в `pricing-service`.

2. **Поддержка SSL:**
   - `gateway_service` автоматически управляет SSL-сертификатами с использованием Let's Encrypt.
   - При запуске контейнера, сервис проверяет наличие действующего SSL-сертификата для домена, используя скрипт `ssl_serts.sh`. Если сертификат отсутствует, он будет автоматически получен.
   - Нginx настроен на работу с HTTPS, обеспечивая безопасное соединение между клиентом и сервисами.

3. **Кэширование:**
   - Для некоторых сервисов, таких как бот-сервис (`bot-service`), включено кеширование. Это позволяет ускорить обработку повторяющихся запросов.
   - Кэш хранится в директории `/var/cache/nginx/bot_cache`, и данные кешируются на 1 час для успешных ответов (HTTP 200).
   - Настройки кэширования конфигурируются в Nginx.

4. **Мониторинг и логирование:**
   - В контейнере также запускается `nginx-prometheus-exporter`, который собирает метрики из Nginx и передает их в систему мониторинга Prometheus.
   - Логи запросов и ошибок записываются в файлы `/var/log/nginx/access.log` и `/var/log/nginx/error.log`, которые могут быть использованы для анализа и отладки.
   - Эти метрики позволяют отслеживать производительность и загрузку, а также позволяют мониторить работу сервисов через Grafana.

5. **SSL-сертификаты и обновление:**
   - Скрипт `ssl_serts.sh` используется для получения сертификатов с Let's Encrypt и для их автоматического обновления.
   - Обновление сертификатов происходит раз в месяц с использованием cron-задачи, которая прописана в контейнере. Если срок действия сертификата близок к истечению, он будет автоматически обновлен.

6. **Запуск и настройки контейнера:**
   - Контейнер запускается с использованием скрипта `start.sh`, который инициирует работу Nginx и `nginx-prometheus-exporter`.
   - Все конфигурационные файлы и сценарии (например, `nginx.conf`, `ssl_serts.sh`, `start.sh`) загружаются в контейнер с помощью Docker, чтобы обеспечить гибкость и возможность кастомизации.
   - При старте контейнера также выполняется инициализация SSL-сертификатов, если они ещё не получены, что позволяет контейнеру работать сразу после запуска.

#### Структура файлов:
- **Dockerfile** — описывает процесс сборки образа для `gateway_service`. В нем указаны все необходимые зависимости и скрипты для работы с Nginx и SSL.
- **nginx.conf** — конфигурационный файл Nginx, который настраивает маршрутизацию запросов и работу с SSL.
- **ssl_serts.sh** — скрипт для получения SSL-сертификатов с помощью Let's Encrypt.
- **start.sh** — скрипт для запуска Nginx и `nginx-prometheus-exporter`.

#### Взаимодействие с другими сервисами:
- `gateway_service` играет роль прокси, который делегирует запросы на другие микросервисы, такие как:
  - `auth-service` для авторизации.
  - `users-service` для управления пользователями.
  - `activities-service`, `plans-service`, `pricing-service` для обработки данных о планах отдыха, маршрутах и ценах.
  - `bot-service` для взаимодействия с Telegram-ботом.

#### Работа с Kubernetes:
- `gateway_service` развертывается в Kubernetes как контейнер, который работает с другими микросервисами через API-шлюз.
- Для этого создаются соответствующие манифесты Kubernetes, такие как `Deployment`, `Service`, `Ingress`, которые обеспечивают масштабируемость и доступность `gateway_service` в кластере.

### Заключение:
`gateway_service` является важным компонентом в архитектуре микросервисов, обеспечивающим централизованное управление запросами, безопасность, кэширование и мониторинг. Он эффективно взаимодействует с другими сервисами, проксируя запросы и обеспечивая гибкость в настройках для улучшения производительности и безопасности системы.
